# Offline verification recovery and checkpoint import

The target remains fixed FP16/SDPA with unchanged18/10GPU layer placement and numerical flags. Saved v4 references were generated from original prompt prefill followed by one-token cached forwards. Re-prefilling the whole corrected prefix can change near-tied FP16 winners, so fallback replay MUST start from the original prompt, not the current long prefix. Each committed token is checked against the model's next argmax before feeding it. After that, each proposal row is scored with the candidate's own teacher-forced history; all selected logits/probabilities are actual model outputs.

The normal parallel verifier is retained only when first rejection and correction agree with the independent saved reference. A disagreement triggers fresh canonical model replay. Its prefix checks and final consistency remain hard requirements; no approximate acceptance, reference-logit substitution, ignored events or precision fallback. Report each row's verification_mode, raw parallel discrepancy, replay scheduling/forward count and BOTH attempt costs. The total includes canonical prefix reconstruction. Stage compute still excludes Accelerate dispatch copies; raw wall remains separate. The fallback trigger is reference-assisted and valid only for this OFFLINE diagnostic, not a deployable online verifier. Do not infer end-to-end speedup or present the new policy as unchanged online SD.

Legacy migration accepts only the audited original v4 commit/source digest, identical experiment config/assets/tokenizer/target precision and compatible torch/transformers/accelerate/CUDA/GPU map flags; only completed-reference checkpoints with no Test2 records. Recompute and check imported Test1 metrics and first-rejection consistency. Preserve imported records/timing exactly with parent-identity provenance; put the archived failure under prior_failure, replay it before further drafting, and preserve its new model evidence. Initial smoke/preflight does not prove every FP16 context identical; the known long-context case is now explicitly tested in the user's new run. Local tiny/random/shape-sensitive tests do not establish pretrained GPU success. If canonical replay fails, preserve diagnostics and stop.

# Protocol v4: two cohorts; crossed redrafters and future-anchor controls

## Models, precision and geometry

Qwen2.5-7B-Instruct verifier stays FP16: embedding/rotary/layers0–17 on GPU0, layers18–27/norm/head on GPU1. Exactly one 1.5B FP16 drafter on GPU1 at a time: Fast-dLLM then unload/GC/clear both GPU caches, then Qwen AR. No quantization, CPU/disk offload or precision fallback. Model/source/dataset revisions remain pinned by source-lock/assets manifest. Token-ID compatibility is checked. Exact cached/parallel target consistency and a strict causal-tail negative control remain mandatory.

Fast-dLLM physical32/active8: fill one remaining MASK per forward, highest top1 confidence in the earliest active subblock, lowest position on ties. Greedy token ties use lowest token ID. Hard anchors are immutable. Only completed physical blocks enter KV; mutable-block forwards never update that cache. Each arm starts from a cold prefix. Same-block future tokens can condition a prediction; a boundary prediction uses the preceding block row and cannot see the next block's anchors. Each conditioning row exports the number of future anchors visible to each probe prediction.

## References and Test1

100 MATH-500 +100 GSM8K, seed42; HumanEval/general deferred by user. Greedy target reference up to256 tokens, stopping at target EOS. A state needs proposal32 plus one bonus token. Up to5 offsets cover the entire eligible reference window including first/last and one physical32 alignment; smoke uses up to3. Progress bin is offset/reference_length: early<1/3, middle<2/3, late otherwise. Short references may have no late eligible state; record actual coverage rather than inventing labels.

Both source drafters receive exactly the same states. Test1 records draft quality (accepted prefix/full acceptance/latency/forwards) separately from conditional nonempty-suffix repairability (macro and pooled match rates, matched islands, reusable-event rate). Empty tails are undefined rates, never zero-filled. Old-context verifier agreement is distinct from reference correctness. Target causal/reference consistency is checked at every proposal.

## Test2 sample and matrix

Freeze a disjoint two-cohort design after all Test1: pilot100 representative +100 enriched; smoke12+12 (24 target events). Representative: allocate capacity-capped quotas across source/benchmark/progress strata, first cover available strata, then balance source/benchmark/progress counts with seeded ties. Sample uniformly without replacement inside each stratum, independent of correct-token/island labels. Inclusion probability n_h/N_h and inverse weight N_h/n_h are saved. The weighted finite-population mean is sum(weight*y)/N over eligible Test1 events; do not call an unweighted balanced-stratum mean representative of the event distribution. Withhold the population estimate if any populated stratum has zero inclusion, any sampled outcome is missing, or weight mass does not equal N. Population values are point estimates; prompt bootstrap in summary.csv is descriptive of each selected cohort, not a design-based population confidence interval. This is conditional on the selected prompts/rejections, not all decoding.

Enriched: from remaining events with at least one reference-correct OLD suffix token, balance source/benchmark/progress then prioritize longest matched islands and larger match count within strata (seeded ties). This is explicitly label-assisted offline selection, with no population weight. Never pool enriched with representative to estimate practical frequency. No duplicates between cohorts; report shortfall, available/selected/empty progress strata and rejection-position/K_correct distributions. Missing positive events are never replaced with zero-correct ones. Both cohorts, frozen design and plans survive resume.

Corrected context convention remains: if r is the1-based first rejection, prefix includes reference through correction index r-1, old suffix starts at draft[r:], horizon L=32-r. Test1 has up to5 prefixes/prompt (smoke3) over a256-token reference, preserving early/middle/late when possible.

For each event freeze ONE plan list, including exact anchor values and bounded oracle subsets. Run it with BOTH redrafters, independent of source: AR→AR, AR→dLLM, dLLM→AR, dLLM→dLLM. Causal constrained AR predicts sequentially, overrides output at KEEP positions and feeds the forced token to subsequent KV processing. It still performs L forwards, including all-KEEP. No bidirectional AR infilling or automatic forward savings are claimed. GPU preflight compares constrained cached AR to independent full-prefix replay and checks future anchors cannot affect earlier AR predictions.

Non-oracle families: fresh-L, direct-rejoin, drafter-confidence, verifier-confidence, ranked old-agreement, natural old-agreement, random and matched-agreement random. Initial ratio0.5, one random repeat. Non-oracle selection accepts only old tokens and previously available old-context feedback. Oracle A keeps all reference-correct OLD tokens. B evaluates up to4 distinct correct-only subsets INCLUDING A, identically for both redrafters, regardless of A's gain. This finite search is not a global upper bound.

Future-content experiment: repeat for3 configured seeds/layouts per event (offsets0/1/2 added as1009*offset to event seed), matched across both models. Actual context lengths come from the different shared-prefix progress states and are exported; this is not a separate truncation intervention. For L>=2 choose up to4 identical anchor positions uniformly in the future half after a probe of min(8,max(1,L//2)) tokens. Compare old content, reference-correct content, guaranteed reference-wrong content, a permutation of original anchor contents, and empirical random tokens sampled from the old suffix. Position/count are identical across variants and redrafters. Correct and wrong construction use offline labels; random is NOT uniform vocabulary noise. Record unchanged shuffled/random content, visible-anchor geometry and probe accepted-prefix gain versus fresh-L and versus future-old. L=1 is explicitly ineligible. Injected correct content is NOT counted as recovered old tokens unless token identity actually equals old. AR probe outputs must exactly match fresh-L; violation stops the run.

Every unique candidate is reverified with Qwen7B, with a hard causal/reference consistency check. Anchors are proposals, never automatically accepted. Deduplicate only exact positions AND contents within one event/redrafter; alias provenance retains representative timing. Complete each model/event pair and mark event complete only after both; resume never changes frozen plans.

## Metrics and timing

ΔA and ΔT always subtract fresh-L for the SAME event/redrafter before cross-architecture comparison. Export redrafter/source/method/rejection/horizon/progress strata and prompt-cluster95% bootstrap CI. Report oracle_keep_gain, bounded_old_mask_search_gain, oracle_future_injection_gain separately; only the first two describe reuse of existing old tokens. Report oracle_A_gain, bounded_oracle_gain, best_nonoracle_gain, wrong_anchor_gain (all anchors wrong), conditioning_gain, oracle_selector_gap, no_bounded_correct_keep_gain and no_observed_gain separately. A non-oracle gain prevents no_observed_gain even when all bounded correct-only oracle masks fail.

T_draft is synchronized single-GPU cold wall time, with prefill and post-prefill mutable time separate. AR mutable time includes processing forced tokens. T_verify compute uses CUDA stage events INSIDE compute modules, AFTER Accelerate input copy and BEFORE output copy; raw verifier wall is stored separately. T_selector is once per event for non-oracle selection, not summed across arms or redrafters. Offline oracle/control construction time is separate. T_wall covers cold drafting plus reverify and Python bookkeeping, excludes plan acquisition, load/setup and online correction/rollback. Raw wall includes communication and is explicitly not the communication-excluded research compute metric; do not interpret wall-minus-stage as transfer time. Report both, never claim end-to-end speedup from these offline measures.

Ten descriptive plots plus source/redrafter-separated CSVs. Identical inference aliases are dependent, not additional independent trials. Bootstrap resamples prompts. Partial runs are not completed pilot results. CLI run --stage references|test1|test2 can separate Pilot A and B while retaining one matching checkpoint identity. Soft budget6h per run call; checkpoint ZIP includes SQLite snapshot, JSONL, plans, coverage, logs/analysis but no weights. This is offline cold replay/reverification, not an implemented online rollback benchmark.


## v4 benefit and cost reporting

Every repair arm retains old_correct_count, correct positions and longest island. summary.csv has K_correct bins0/1/2–3/4+, first-correct-position bins and island-length strata, all separated by cohort/source/redrafter/method. oracle_comparison.json places the3oracle types beside selector gains, with no-old-opportunity flags. No gain when K_correct=0 is not evidence that a nontrivial oracle infiller failed.

benefit_outcomes.csv reports ΔA>0, equal-A with cheaper drafting, equal-A without saving, loss capped exactly at first false KEEP, loss with false KEEP, and loss without false KEEP. Merely co-occurring false KEEP is not labeled the unique cause. efficiency.csv exports A/T_draft, A/(T_draft+T_verify_compute) and raw-wall counterpart, as ratios of totals within one cohort/source/redrafter/method. ΔA and ΔT remain paired to the same model/event fresh-L. Stage compute excludes dispatch copies; raw wall includes them. A tiny single-run negative ΔT is descriptive, not proof of a stable latency gain. Identical-content inference aliases and3seed repeats are correlated, not new independent events. There is still no online rollback, learned selector, world model or end-to-end speedup claim.
